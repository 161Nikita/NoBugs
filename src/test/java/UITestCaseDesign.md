# Тест-кейсы для UI (Итерация 2)

---

## Предусловия для всех тест-кейсов

1. Пользователь авторизован в системе с ролью `USER`.
2. У Пользователя создан аккаунт (счет).
3. Пользователь находится на странице User Dashboard по URL: `http://localhost:3000/dashboard`.

---

## 1. Депозит денег пользователем (Пополнение счета)

### 1.1. Успешное пополнение собственного активного счета (Позитивный кейс)

* **Связанный API кейс:** `POST /api/v1/accounts/deposit`
* **Шаги:**
1. Кликнуть по кнопке `Deposit Money`.
2. Кликнуть по выпадающему списку под меткой `Select Account:`.
3. Выбрать из открывшегося списка любой доступный счет (например, `ACC5467B089 (Balance: $0.00)`).
4. В поле ввода под меткой `Enter Amount:` ввести валидное положительное число в пределах лимита (5000 вкл).
5. Нажать на кнопку **`Deposit`**.
* **Ожидаемый результат:**
  * Запрос уходит на сервер в соответствии с требованиями (тело запроса)
  * Ответ от сервера приходит в соответствии с требованиями (тело ответа)
  * Приложение отправляет повторный GET-запрос на `/api/v1/accounts` для обновления данных
  * Баланс увеличивается на сумму пополнения в базе данных и на UI

---

### 1.2. Попытка пополнения на сумму, превышающую лимит > 5000 (Негативный кейс)

* **Связанный API кейс:** `POST /api/v1/accounts/deposit`
* **Шаги:**
1. Кликнуть по кнопке `Deposit Money`.
2. Кликнуть по выпадающему списку под меткой `Select Account:`.
3. Выбрать из открывшегося списка любой доступный счет (например, `ACC5467B089 (Balance: $0.00)`).
4. В поле ввода под меткой `Enter Amount:` ввести невалидное число, превышающее лимит (например, `5000.01`).
5. Нажать на кнопку **`Deposit`**.
* **Ожидаемый результат:**
  * Запрос уходит на сервер в соответствии с требованиями (тело запроса)
  * Ответ от сервера приходит в соответствии с требованиями (код 400 Bad Request и тело ответа с ошибкой валидации лимита)
  * На UI всплывает модальное окно alert с текстом `Please deposit less or equal to 5000$.`
  * Баланс счета в базе данных и на UI не изменяется

---

### 1.3. Проверка дефолтного состояния экрана и навигации назад (Позитивный кейс интерфейса)

* **Шаги:**
1. Кликнуть по кнопке `Deposit Money`.
2. Проверить дефолтное состояние полей ввода и плейсхолдеров.
3. Нажать на синюю кнопку **`Home`** в правом нижнем углу.
* **Ожидаемый результат:**
  * В выпадающем списке `Select Account:` по умолчанию отображается плейсхолдер `- Choose an account -`
  * В поле ввода `Enter Amount:` по умолчанию отображается серый текст-подсказка `Enter amount`
  * Список счетов и балансов в дропдауне соответствует данным, полученным из успешных GET-запросов к `/accounts`
  * При нажатии на кнопку `Home` происходит возврат пользователя на главную страницу дашборда (`/dashboard`)

## 2. Перевод денег с одного аккаунта на другой

### 2.1. Успешный перевод денег стороннему клиенту (Позитивный кейс)

* **Связанный API кейс:** `POST /api/v1/accounts/transfer`
* **Шаги:**
1. Кликнуть по кнопке `Make a Transfer`.
2. Кликнуть по выпадающему списку под меткой `Select Your Account:`.
3. Выбрать из открывшегося списка свой счет с достаточным балансом.
4. В поле ввода под меткой `Recipient Name:` ввести имя получателя.
5. В поле ввода под меткой `Recipient Account Number:` ввести номер счета получателя.
6. В поле ввода под меткой `Amount:` ввести валидную сумму в пределах лимита (10000 вкл) и не превышающую баланс отправителя.
7. Установить чекбокс `Confirm details are correct`.
8. Нажать на кнопку **`Send Transfer`**.
* **Ожидаемый результат:**
  * Запрос уходит на сервер в соответствии с требованиями (тело запроса)
  * Ответ от сервера приходит в соответствии с требованиями (тело ответа с сообщением "Transfer successful")
  * Приложение отправляет повторный GET-запрос на `/api/v1/accounts` для обновления данных
  * Баланс счета-отправителя в базе данных и на UI уменьшается на сумму перевода

---

### 2.2. Попытка перевода суммы, превышающей текущий баланс отправителя (Негативный кейс)

* **Связанный API кейс:** `POST /api/v1/accounts/transfer`
* **Шаги:**
1. Кликнуть по кнопке `Make a Transfer`.
2. Кликнуть по выпадающему списку под меткой `Select Your Account:`.
3. Выбрать из открывшегося списка свой счет (например, с балансом `$0.09`).
4. В поле ввода под меткой `Recipient Name:` ввести имя получателя.
5. В поле ввода под меткой `Recipient Account Number:` ввести номер счета получателя.
6. В поле ввода под меткой `Amount:` ввести сумму, которая строго больше баланса выбранного счета (например, `100`).
7. Установить чекбокс `Confirm details are correct`.
8. Нажать на кнопку **`Send Transfer`**.
* **Ожидаемый результат:**
  * Запрос уходит на сервер в соответствии с требованиями (тело запроса)
  * Ответ от сервера приходит в соответствии с требованиями (код 400 Bad Request и тело ответа с ошибкой)
  * На UI всплывает модальное окно alert с текстом ошибки
  * Баланс счета-отправителя в базе данных и на UI не изменяется

---

### 2.3. Попытка отправки формы перевода без установки обязательного чекбокса (Негативный кейс)

* **Шаги:**
1. Кликнуть по кнопке `Make a Transfer`.
2. Выбрать активный счет в списке `Select Your Account:`.
3. Заполнить корректными данными поля `Recipient Name:`, `Recipient Account Number:` и `Amount:`.
4. Оставить чекбокс `Confirm details are correct` неустановленным.
5. Нажать на кнопку **`Send Transfer`**.
* **Ожидаемый результат:**
  * Новый запрос к API (`POST /api/v1/accounts/transfer`) на сервер не отправляется
  * На UI всплывает модальное окно alert с текстом `Please fill all fields and confirm.`
  * Баланс счета-отправителя в базе данных не изменяется

---

### 2.4. Попытка отправки формы с незаполненными обязательными полями (Негативный кейс)

* **Шаги:**
1. Кликнуть по кнопке `Make a Transfer`.
2. Оставить все поля ввода (`Select Your Account:`, `Recipient Name:`, `Recipient Account Number:`, `Amount:`) пустыми.
3. Установить чекбокс `Confirm details are correct`.
4. Нажать на кнопку **`Send Transfer`**.
* **Ожидаемый результат:**
  * Новый запрос к API (`POST /api/v1/accounts/transfer`) на сервер не отправляется
  * На UI всплывает модальное окно alert с текстом `Please fill all fields and confirm.`
  * Баланс счета-отправителя в базе данных не изменяется

---

### 2.5. Переключение на вкладку повторного перевода и поиск зарегистрированных пользователей (Позитивный кейс интерфейса)

* **Связанный API кейс:** `GET /api/v1/users`
* **Шаги:**
1. Кликнуть по кнопке `Make a Transfer`.
2. Нажать на кнопку `Transfer Again`.
3. В появившемся поле под меткой `Search by Username or Name:` ввести поисковый запрос (например, `7878`).
4. Нажать на кнопку `Search Transactions`.
* **Ожидаемый результат:**
  * Интерфейс скрывает форму отправки нового перевода и отображает блок поиска пользователей
  * Поле поиска до ввода содержит плейсхолдер `Enter name to find transactions`
  * Ниже отображается заголовок `Matching Transactions`
  * Запрос уходит на сервер в соответствии с требованиями ручки `GET /api/v1/users` с query-параметрами поиска
  * Ответ от бэкенда успешно обрабатывается, и найденные пользователи выводятся списком ниже заголовка

---

### 2.6. Проверка дефолтного состояния экрана перевода и навигации назад (Позитивный кейс интерфейса)

* **Шаги:**

  * Чекбокс `Confirm details are correct` не установлен
  * При нажатии на кнопку `Home` происходит возврат пользователя на главную страницу дашборда (`/dashboard`)

## 3. Изменение имени пользователя в профиле (name)

### 3.1. Успешное изменение имени на валидный формат (Позитивный кейс)

* **Связанный API кейс:** `PUT /api/v1/customer/profile`
* **Шаги:**
1. Кликнуть по блоку профиля в правом верхнем углу (с текущим именем `Noname` и юзернеймом `@nikita1`).
2. В поле ввода под меткой `Edit Profile` ввести строго два слова, разделенные одним пробелом (например, `Nikita Krapivin`).
3. Нажать на кнопку **`Save Changes`**.
* **Ожидаемый результат:**
  * Запрос уходит на сервер в соответствии с требованиями (тело запроса содержит измененное поле name)
  * Ответ от сервера приходит в соответствии с требованиями (код 200 OK)
  * Приложение отправляет повторный GET-запрос на `/api/v1/customer/profile` для обновления данных
  * На UI всплывает модальное окно alert с текстом `Name updated successfully!`
  * Новое имя пользователя успешно обновляется в базе данных, а на UI в блоке профиля в верхнем углу отображается `Nikita Krapivin`

---

### 3.2. Проверка дефолтного состояния экрана профиля и навигации назад (Позитивный кейс интерфейса)

* **Шаги:**
1. Кликнуть по блоку профиля в правом верхнем углу.
2. Проверить дефолтное состояние поля ввода и плейсхолдера.
3. Нажать на синюю кнопку **`Home`** в правом нижнем углу.
* **Ожидаемый результат:**
  * В единственном поле ввода по умолчанию отображается серый текст-подсказка `Enter new name`
  * При нажатии на кнопку `Home` происходит возврат пользователя на главную страницу дашборда (`/dashboard`)

---
